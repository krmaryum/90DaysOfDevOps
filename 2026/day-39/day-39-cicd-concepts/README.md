Day 39 of #90DaysOfDevOps – What is CI/CD?

Today was focused on understanding the foundations of CI/CD before creating actual pipelines.

One important lesson I learned is that CI/CD is not a tool. It is a software delivery practice that helps teams automate building, testing, and deploying applications reliably and consistently.

Key topics covered today:

• What automation means in software delivery
• What a pipeline is and why it is important
• Problems with manual deployments
• The meaning of "It works on my machine" and how CI/CD helps solve it
• Continuous Integration (CI)
• Continuous Delivery (CD)
• Continuous Deployment (CD)
• Pipeline Anatomy:

* Trigger
* Stage
* Job
* Step
* Runner
* Artifact

I also explored a real open-source project and analyzed its GitHub Actions workflow to understand how CI/CD is used in production environments.

One takeaway that stood out to me:

A failed pipeline is not necessarily a problem. In many cases, it is doing exactly what it was designed to do—preventing broken code from reaching production.

To reinforce these concepts, I documented detailed notes, created pipeline diagrams, studied workflow structures, and completed a set of CI/CD practice questions.

Looking forward to the next step: building real GitHub Actions workflows and automating software delivery pipelines.
